# 项目收尾

作者：jiaqi ding

将当前工作成果整理为可验证、可继续维护的状态；在 Git 仓库中形成准确提交，最后处理收尾范围内的剩余改动。本轮收尾完成不代表整个项目完成。

先识别项目根目录、当前工作范围和 Git 根目录。针对整个仓库收尾时，默认包括最后分类处理仓库内其他任务留下的改动；针对独立子项目或指定任务收尾时，只处理该范围及必要的共享状态更新，不因属于同一仓库扩展到其他子项目。用户要求保留的改动原样保留。这个范围不包含新增功能、替未完成的其他任务继续开发、推送或部署。

非 Git 项目同样执行成果整理、相称验证、状态更新和归档，跳过暂存、提交和 Git 检查，不为收尾自动初始化仓库。最终报告实际成果与剩余工作，不报告工作区干净。

## 第一阶段：提交本次成果

1. 阅读当前目录及上级适用的 `AGENTS.md`、README、贡献指南和构建说明。
2. 检查当前分支、`git status --short`、暂存区与工作区 diff、未跟踪文件；结合会话与用户指定范围，辨别本次成果、生成物、敏感文件和无关或归属不明的修改。记录原有暂存状态；文件发生变化或已被暂存，都不能单独证明它属于本次任务。
3. 整理本次任务的修改与相关文件，其他任务的改动留到最后阶段处理：
   - 清除确定无用的临时、重复、调试和过时文件。
   - 统一源码、文档、配置、部署脚本和部署产物之间的版本、命名及引用。
   - 进行必要的小范围重组、移动、优化或重构，并同步修正引用。
   - 保留有明确用途的本地部署文件，即使它们被 Git 忽略。
   - 按项目约定将有追溯价值、已结束或退出当前工作的过程和旧交接材料移入所属范围的 `archive/`，注明完成、搁置、取消或被替代的状态及必要原因，修正引用。现行成果和仍有效知识保留在正式位置；尚需继续的工作保留在当前任务入口，不为归档额外创建 HISTORY 文档。
4. 按改动风险运行必要的测试、构建、格式或配置检查，并对本次 diff 执行空白错误检查。已有验证仍覆盖最终改动时复用其证据；只有后续修改、失败或未解决风险需要时才补跑或扩大验证。
   调研、设计和宣传成果采用对应的来源核对、内容检查或渲染检查，不机械套用代码测试。依据实际检查结果更新所属范围的 `STATUS.md` 或等价入口，记录成果位置、验证情况、未完成项和下一步；整体状态仅补充必要的跨子项目变化。这些更新在提交前完成，后续整理改变状态时同步修正。
5. 检查密钥、密码、令牌、真实 `.env`、私钥及其他敏感信息；不得将其加入提交。
6. 再次审阅待提交 diff，只暂存属于本次任务且安全的内容，对实际待提交内容执行 `git diff --cached --check` 或等价检查，创建内容准确的中文 Git 提交。暂存区已有其他任务的内容时，采用能暂时保留其暂存状态且只提交本次内容的方式，不能直接把整个暂存区提交。同一文件内的混合修改无法安全分离时，保留该文件，先完成可独立提交的成果；最终集中说明阻塞。
7. 核对提交实际包含的文件与 diff。本次成果处理完毕后进入最后阶段；没有需要提交的变化时，不创建空提交。存在无法处理的阻塞时，仍可整理独立且已获准的剩余项，但不能声称本次成果已全部完成。

## 最后阶段：整理剩余改动并验收

1. 重新检查 `git status --short`、暂存区与工作区 diff、未跟踪文件。逐项判断收尾范围内剩余改动的用途、完整性、引用与入库要求；整个仓库收尾时，不因属于其他任务就跳过。范围外改动保持原状。
2. 按实际用途处理：
   - **适合入库的有效成果**：内容完整、用途明确且可验证时，完成必要验证和敏感信息检查，再按任务或目的分别创建中文提交。原先已暂存不等于可以直接提交。
   - **确定无用的残留**：核实目标及引用后，清理临时、调试、重复或过时文件，以及有证据证明无用的残留改动。保留同一文件中的有效成果，不按“非本任务”或“未跟踪”直接判定无用。
   - **需要保留的本地文件**：按项目约定安置配置或产物；确属长期不入库类别时才调整精确的忽略规则。已跟踪文件不能靠新增忽略规则隐藏修改，不擅自取消跟踪。安置会破坏运行路径或引用时，保留并列出所需决定。
   - **无法判断或尚未完成的改动**：保持内容与暂存状态，不猜测其用途，不替另一个任务继续开发。完成其余可处理项后，集中说明具体文件、建议处置和需要用户决定的事项。
3. 核对最后阶段的提交与清理结果，对新增改动补充相称验证；已有检查仍适用时不重复执行。
4. 最终运行 `git status --short`，以输出为空作为整个工作区干净的标准。只有本次成果和剩余整理均完成、必要验证通过，才报告收尾完成；子项目收尾分别说明范围内结果和仓库剩余状态，范围外改动不阻塞局部收尾，也不能据此声称整个工作区干净。仍有阻塞或明确要求保留的改动时，如实报告，不为了满足干净目标突破用户限制。

忽略文件可以按用途保留；工作区干净不代表删除所有本地文件。

## 安全边界

- 不擅自丢弃、覆盖或删除归属不明的修改。
- 不使用 `git reset --hard`、`git checkout --` 等破坏性命令清理工作区。
- 删除或迁移前核实目标及引用；已有授权覆盖的常规操作直接完成，真正缺少授权时说明具体操作。
- 不通过无差别提交、丢弃有效成果、临时 stash、隐藏跟踪状态或添加宽泛忽略规则制造干净状态。
- 不提交敏感文件或明显不应入库的生成物；不因收尾而 push、部署或修改其他仓库。
- 无法安全判断的项只阻塞受影响的操作，先完成其他可处理项，再集中说明所需决定。
- 若验证失败，先在授权范围内修复；无法修复时不得声称收尾完成。

## 最终报告

简要报告：

- 本次成果与最后阶段剩余改动的主要处理结果；
- 状态入口与必要归档的更新；
- 已执行的验证及结果；
- Git 项目的提交哈希、提交说明及 `git status --short` 是否为空；
- 未完成项、保留改动或所需决定；
- 保留但未提交的忽略文件或敏感配置（只说明类型和路径，不泄露内容）。
