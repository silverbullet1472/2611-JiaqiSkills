# 活人感 PPT

## 目标

让视觉汇报像实际做事的人整理出来的材料。使用准确名称、正常书面语和清楚的信息层级，不靠口号、假口语或戏剧化断句制造“活人感”。

本 Skill 负责页面文案、内容取舍和呈现关系。创建或修改具体文件时，同时使用对应的 PPT、HTML、前端设计或文档工具。

发生冲突时，先保护事实、原意、证据强度和来源对应，再满足受众、用途和编辑范围，最后调整文风与版式。来源对应在制作文档中维护，不等于必须在画面展示。自然表达不等于口语化；AI 高频句式只是编辑线索，不用于判断作者身份。

## 演示画面与制作备注

- 默认在电脑屏幕上展示。HTML 汇报按桌面视口设计和验证，不投入窄屏、手机端或响应式适配，也不安排相应检查；用户明确要求其他展示设备或响应式支持时，再按要求处理。
- 默认不在汇报画面添加防御性说明、免责声明、待核提示、长篇统计口径页脚，以及“来源”“查看依据”等按钮、链接或弹窗入口。新建和优化现有汇报均按此执行；用户明确要求展示时再添加。
- 出处、核验状态、引用对应和制作注意事项保存在素材清单、讲者备注或其他工作文档中，不自动生成可见附录，也不把这些备注标成“上屏页脚”。素材原图自带的署名和日期保留。
- 正文应准确而简洁。例如需要表达预测情景时，直接写“情景推演”；需要表达媒体或机构的说法时，在标题或正文中自然归属。不要在每页另加“待核”“不代表本人表态”“不是已证实事实”等说明小字，也不要用删除备注的方式把推演、指控或辅助成果改写成确定事实。
- 完成后检查：观众是否被迫阅读只供制作者核对的信息；如有，将其移回工作文档。

按用户要求选择审查或实施。只要求评价、检查或建议时报告具体问题；要求优化或改稿时直接修改获准内容。局部调整只处理相关页面或元素，不因此重做整套材料。

## 工作流程

### 1. 确认材料类型

- 只处理以观看、浏览和讲解为主要使用方式的视觉材料。
- 覆盖单页或整套 PPT、PPTX、滚动式 HTML 汇报、可视化方案页和展示型长页面。
- 遇到讲稿、逐字稿、长篇报告或文章时，改用相应写作 Skill。
- 未指定受众时，默认面向没有相关专业背景的大众，按科普方式组织文案。用户明确指定受众或已有上下文明示受众时，以该受众为准，相应调整信息重点、术语、背景解释与技术深度。
- 不预设受众的组织身份、固定叙事顺序或页面比例。根据用户提供的场景决定。
- 优先沿用已明确的受众、用途和约束；常规表达与排版选择自行处理，只有缺少的信息会实质改变内容或结论时才提问。
- 区分文字润色与页面重构。只要求润色时保留独立信息及页面职责；要求精简、重构或制作汇报时，可按观看任务取舍、拆页和调整图文，但不能省掉影响判断的条件与反例。

### 2. 找出每页的主要任务

先用一句普通话说明这一页要让观看者看懂什么，再决定标题、文字和视觉形式。

- 先判断受众需要理解意义、作出选择，还是学习原理。原材料讲得最详细的部分，不一定是页面应该重点讲的部分；不要直接把技术报告压缩成幻灯片。
- 面向非专业受众介绍进展时，优先说清发生了什么、为什么值得关注、与熟悉的事情有什么联系。只保留完成这个理解任务所需的技术解释；专业评审或原理教学则保留相应技术深度。
- 用有依据的具体参照帮助受众理解分量，例如难题持续了多久、悬赏或投入规模、实际应用、前后耗时和工作量。选择能解释意义的参照，不为了震撼堆数字，也不把悬赏写成已获奖金、把潜在应用写成已经落地。
- “太专业”往往是选错了要讲的信息，不能只把术语翻译成更长的白话。删去不服务本页任务的推导和机制，把空间留给受众需要的背景与意义。

- 一页或一个滚动段落可以包含多项内容，但只能有一个主要任务。
- 区分阶段结论、过程说明、数据比较、结构关系、案例展示和下一步安排。
- 不按模板强行安排“结果优先”“过程在后”或其他固定顺序。
- 整套重构前先识别关键结论、支撑材料及跨页依赖；局部改稿只核对相关内容。影响正文含义的条件与结论一起简洁表达；制作核对信息按“演示画面与制作备注”处理。

大幅写作或改稿前读取 [references/copywriting.md](references/copywriting.md)。

### 3. 按重要程度安排页面分量

- 让标题承担导航作用。只有确实需要被记住的结论，才写成结论型标题。
- 根据内容对当前页面的作用决定字号、位置、面积和颜色，不因数字具体就自动放大。
- 把普通实施动作放在正文、流程节点或图注中，不包装成重大成果。
- 页面已有真实界面、图片或文件结构时，让画面承担说明，文字只补充画面无法表达的信息。

### 4. 选择与内容一致的视觉关系

不要把所有信息都排成同等大小的色块。先判断内容之间的关系，再选择版式。

- 有先后依赖时使用流程或时间线。
- 比较两个对象时使用明确的左右、上下或同轴对照。
- 有主次、包含或归属关系时使用层级、树形或面积差。
- 多个字段需要逐项对应时使用表格或对齐列表。
- 展示真实材料时优先保留材料本身，避免用装饰性卡片替代证据。

规划或调整布局时读取 [references/visual-semantics.md](references/visual-semantics.md)。

### 5. 写页面文案

- 使用准确的工作名称、对象名称、动作和数字。
- 保留原材料中的事实、数据口径、限定条件和来源归属。发现缺失或矛盾时指出具体位置，不为了让页面完整而补造数字、成果或上线状态。
- 压缩句子时同时保留否定范围、归因和不确定性；标题、主数字与图表也不能比证据更强。移动陈述时同步移动来源，不能让一个引用看起来支持整页未经支持的结论。
- 原文的实质判断可能超出证据时，明确指出缺口，不静默改成另一种判断；能独立完成的页面继续处理，只有影响核心结论的缺口才需要先确认。
- 用正常书面语表达，不刻意模拟聊天，也不把标题写成诗行。
- 清理没有增加信息的口号、黑话、模型式转折、抽象包装和机械排比；保留必要术语、真实区别和完整清单，不按词表机械删除。
- 避免“这一页告诉你”“我们先来看”“你可能以为”等主持式路标。
- 标题、引导语、数据卡、图注和按钮各做一件事，不互相重复。
- 文案服务扫读。能用短语说清的标签不写成长句；需要解释条件时使用完整句子。

### 6. 完成后改稿

整套新建、大幅改稿或完整审查时，读取 [references/revision-checklist.md](references/revision-checklist.md)，逐页检查标题分量、信息层级、图文分工、视觉关系和模型腔。小范围修改只检查受影响的内容及相邻一致性。

修改时先找原句想表达的事实，再用普通句子重写。不要只把一个漂亮句式换成另一个漂亮句式。

对压缩、引用或句式保护的边界拿不准时，读取 [references/editing-examples.md](references/editing-examples.md)。已自然、准确且适合页面的文字可以保留，不为显示改动而改写。

例如，向非专业受众介绍数学突破，重点可以是“七大千禧年难题之一、每题悬赏100万美元、与天气预报等应用有关”，而不是展开“平滑外力、有限时间奇点”的证明结果。这里学的是根据受众选择信息，不是固定采用奖金或省略所有技术内容。

交付修改后的材料，或与审查范围对应的具体建议。实际文件的渲染和功能验证由相应工具流程完成；只看过文案时，不声称版式已经验收。

不强制输出诊断标签、评分或逐条修改报告。必要时简要说明重要取舍和待确认的问题；分批交付时写清已完成范围，不能把阶段稿称为整套完成。

## 边界

- 不负责演讲稿、逐字稿和口头表达节奏。
- 不把任何行业、项目或组织的汇报习惯写成普遍规律。
- 不固定要求结果、过程、证据或下一步出现在哪个位置。
- 不内置准确率、成本、抽查、上线状态等特定业务口径。
- 不负责链接、媒体播放、打包发布或浏览器兼容等技术验证；需要时交给相应文件或开发 Skill。
- 不强制某种主题、配色、字体、比例或页面数量。
