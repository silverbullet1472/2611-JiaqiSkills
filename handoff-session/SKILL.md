# 会话交接

作者：jiaqi ding

让没有当前聊天记录的下一会话知道目标、当前进度和下一步。默认简短，只保留影响续接的信息；已有文档引用路径，不重复抄写。

## 整理上下文

以原始目标、已确认决策和用户最新要求为准。优先使用本会话已确认的信息，遵守适用的项目规则，只补查影响续接的缺失或易变状态，不为交接重新调查项目或重跑已完成的验证。目标明确时直接执行；只有无法判断且会显著改变交接内容时才提问。

优先更新所属工作范围已有的 `STATUS.md` 或等价状态入口，保持现状精简，区分已产出、已验证和待确认。根状态只记录整体重点和依赖，局部细节就近维护，不重复抄写。已确认且有明确归属的长期知识，最小化更新对应文档。

## 选择交接入口

状态文件已足够支持续接时，直接用它作为交接入口，不另建副本。需要保存本次会话特有的续接细节，或没有合适状态入口时，再建立独立交接文件。

在环境允许的范围内，优先使用用户指定位置，其次沿用项目约定，否则放在能完整承载当前任务的最小工作范围下的 `handoffs/`；跨子项目的整体交接放根目录 `handoffs/`。按任务归属选择位置，不以终端当前目录决定，不要求所有层级都建立交接目录。没有可用项目目录时使用环境指定的交付目录，再无约定时使用系统临时目录下的 `codex-handoffs/`。

默认文件名为 `handoff-YYYYMMDD-HHmmss-主题.md`，已有命名约定时沿用。独立文件引用现行状态与材料，补充接续细节；在已有局部状态或入口中链接当前交接文件。

内容按以下四项组织，可合并或省略无内容的栏目，不必套用固定模板：

- **目标**：下一会话要继续完成什么。
- **当前进度**：已完成什么、停在哪里，以及必要的验证结果或证据位置。
- **下一步**：第一项具体行动及其余未完成事项；若被阻塞，说明解除阻塞需要什么。
- **必要约束与来源**：影响续接的决定、未解决问题和关键文件，区分已确认事实与待确认项。

记录续接所需的工作目录；Git 任务核对并注明分支和相关未提交改动。仅在任务依赖时补充执行环境、复现命令或已有校验要求。只保留下一会话容易重犯的失败尝试及原因，不保留探索流水账。

使用下一会话能定位的路径。已知要跨环境续接时，选择可访问的位置或注明需携带的文件，不依赖仅在当前主机存在的临时文件。

## 检查与交付

保存后简短核对：目标和第一步是否明确，完成状态是否准确，关键约束是否遗漏，引用路径是否有效。检查交接内容即可，不扩大为原任务的重新验收。

最终提供所选交接入口（状态文件或独立交接文件）的完整路径和可复制的新会话提示词，并简述实际更新的位置。提示词只指向入口，不重复列出其中的来源，例如：

> 请读取 `<交接入口完整路径>`，按其中的目标和下一步继续工作。只补查执行所需的缺失或已变化信息。

确有执行前置条件时，在交接文件中写明；不要要求用户粘贴完整旧会话。

## 边界

- 只交接用户指定的工作范围，不带入无关工作线。
- 不记录密钥、令牌等秘密；其他敏感信息只保留续接必需的最小内容。
- 不因交接而额外提交、推送、归档、删除、发布或修改外部系统。
