# AI 原生项目建设

作者：jiaqi ding

让没有旧会话记录的 Agent 能找到当前依据、接续工作并验证成果。根据实际任务建立最小结构，沿用已有合理约定，不套固定目录模板。

## 识别范围

阅读适用的项目规则、入口和已有材料，识别项目根目录、独立工作范围与 Git 仓库根目录。区分初始化与维护：初始化补齐必要基础；维护只处理当前需要解决的结构、入口、状态和引用问题，不借机重构业务实现。

## 建立项目基础

- `README.md`：说明项目目标、目录导航和当前有效材料入口；具体运行、制作和验证方式可以链接到对应子项目。
- `AGENTS.md`：记录本项目需要的工作约定、按需阅读路径，以及状态、交接和归档的位置。保留已有内容，不重复通用规则。
- `STATUS.md`：保存当前阶段、已完成和未完成事项、阻塞、下一步及成果和验收依据的位置。已有等价状态入口时沿用。
- 根据已有材料和正在开展的工作建立目录。项目根目录下的工作目录优先采用 `YYMMDD-语义名称`，日期为工作开始日期，后续更新不改日期，例如 `261026-Phase1Dev`、`261024-ReportMaterial`、`261025-UIPrototype`。管理目录和工具要求的目录沿用固定名称；不为命名偏好批量改名。
- 目录可以承载完整阶段，也可以承载独立的调研、设计或开发工作。跨目录依赖通过相关入口或任务文档明确引用，说明当前采用的设计、实现或材料，不靠日期推断。
- 只在需要时建立局部 README、状态入口、`handoffs/` 和 `archive/`。不预建空目录，不额外建立 HISTORY 文档；重要决定就近记录，有独立维护价值时再拆分。

初步 demo 应说明验证了什么、尚未验证什么，以及是否作为正式实现继续使用。不能把探索产物自动视为已确认方案。

## 写入持续协作约定

将以下约定简要融入项目规则，并使用实际路径，不复制一整套无关模板：

- 开始工作先读相关入口与当前状态，再按需读取材料；针对本次任务核对必要的实际状态，不默认遍历全部文档和归档。
- 正在推进的工作应有目标和完成标准。区分计划、已产出、已验证和待确认；需求变化应更新当前依据，不能把取消或缩减任务记作完成。
- 重要进展、阻塞、路线变化和交接时及时更新状态，不等调用技能才记录。状态是可改写的现状，不是无限追加的会话日志。
- 信息放在能完整承载任务的最小工作范围内。根状态记录整体重点和依赖，局部状态承载执行细节；同一事实在一个位置维护，其他地方引用。
- 简单交接直接使用状态文件。需要独立交接材料时放在对应范围的 `handoffs/`，整体交接放根目录；内容以接续细节和引用为主。
- 已完成、搁置、取消或被替代的过程材料，有追溯价值时移入所属范围的 `archive/`，注明日期、状态和必要原因或替代位置。现行成果和仍有效的知识留在正式位置；仍承诺执行的任务保留在当前任务入口。

## Git 基础

初始化默认包含 Git。先检查当前目录是否已经属于仓库；属于上级仓库时沿用，不意外建立嵌套仓库。没有仓库时在项目根目录初始化。

按实际内容补充 `.gitignore`，排除秘密、缓存和不应入库的临时或生成文件，不宽泛忽略正式材料、状态或交接文件。审查后仅暂存并提交本次建立或调整的基础文件，形成中文初始基线提交；已有项目中的其他改动不自动纳入。维护模式不默认提交，由用户要求或项目收尾处理。

不默认配置远程、推送或改变全局 Git 设置。Git 不可用或提交身份缺失时，完成其余基础并明确说明未完成的 Git 步骤，不编造身份。

## 维护与验收

维护时聚焦入口失效、状态与实际成果不一致、重复或过时说明，以及需要归档的材料。移动前检查引用并同步更新，保留无法判断归属的内容。

检查新会话能否找到目标、现行依据、当前状态、成果验证方式与第一步；核对修改后的路径和 Git 状态。简要报告实际建立或调整的内容、入口位置、提交结果及未完成项。

本技能建立共享约定；`handoff-session` 负责接续，`finalize-project` 负责成果验收和收尾。三者通过项目文件协作，不要求依次或相互调用。
